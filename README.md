# AI-accounter — автоматизация Кабинета налогоплательщика РК

Автоматическая подача налоговой отчётности в [knp.kgd.gov.kz](https://knp.kgd.gov.kz)
через Playwright + ЭЦП (NCALayer). Полный цикл без участия человека:
вход по ЭЦП → заполнение ФНО → подпись → отправка → отзыв.

## Что уже работает

| Этап | Статус | Скрипт |
|---|---|---|
| Вход в кабинет по ЭЦП | ✅ проверено многократно | `scripts/login.js` |
| Навигация по каталогу форм (70 форм) | ✅ | `scripts/find-form.js` |
| Заполнение 910.00 по нулям | ✅ | `scripts/declare-910.js` |
| Подпись ЭЦП и отправка | ✅ документ принят ОГД | `scripts/declare-910.js --submit` |
| Отзыв отчётности (007.00) | ⚠️ готов, упирается в справочник КНП | `scripts/recall.js` |

## Как это устроено

Ключевая сложность — ЭЦП. Сайт не подписывает данные сам: он открывает
WebSocket на `wss://127.0.0.1:13579` и просит локальный **NCALayer** подписать
XML. NCALayer показывает **нативное окно на JavaFX**, которое Playwright не видит
в принципе — это не часть страницы.

```
Playwright (Chromium, CDP :9222)
      │  клик «Выбрать ЭЦП» / «ПОДПИСАТЬ И ОТПРАВИТЬ»
      ▼
  knp.kgd.gov.kz  ──WebSocket──▶  NCALayer (javaw)
                                      │ нативный диалог JavaFX
                                      ▼
                          scripts/nca-sign.ps1 (UI Automation)
                          путь к ключу → пароль → выбор сертификата
                                      │
                                      ▼
                          подпись возвращается на сайт
```

Диалог NCALayer управляется через **UI Automation**: JavaFX отдаёт полноценное
дерево доступности, поэтому работаем по именам элементов, а не по координатам.

### Три подводных камня, на которых всё ломалось

1. **Кодировка.** PowerShell 5.1 читает `.ps1` без BOM как ANSI, и кириллические
   имена элементов («Пароль», «Подписать») превращаются в мусор — ничего не
   находится. Все скрипты обязаны быть в **UTF-8 с BOM**.

2. **Фокус окна.** Windows не даёт фоновому процессу забрать фокус, и SendKeys
   с паролем улетал в соседнее окно. Решение — `AttachThreadInput` + явная
   проверка `GetForegroundWindow()` перед вводом.

3. **Масштаб дисплея.** NCALayer отдаёт координаты **самого окна** в физических
   пикселях, а координаты своих **JavaFX-элементов** — в логических. При
   масштабе 150% клик по «Подписать» уезжал на треть экрана мимо. Решение —
   домножать координаты элементов на `DpiScale`.

Ещё: `SendKeys` не умеет кириллицу (шлёт VK текущей раскладки), а путь к ключу
почти всегда содержит кириллицу — поэтому он вставляется через буфер обмена.

## Запуск

```powershell
# 1. Долгоживущий браузер с CDP (один раз, держать открытым)
node scripts/start-browser.js

# 2. Переменные окружения (см. .env.example)
$env:ECP_PASSWORD = '<пароль от ЭЦП>'
$env:ECP_KEY_PATH = 'C:\путь\к\ключу.p12'
$env:KNP_OKED     = '<код вида деятельности>'
$env:KNP_OGD      = '<код органа госдоходов>'

# 3. Вход
node scripts/login.js

# 4. Декларация 910.00 по нулям — БЕЗ отправки
node scripts/declare-910.js "1 полугодие" 2026 "Дополнительная" $env:KNP_OKED

# 5. То же самое с реальной подачей
node scripts/declare-910.js "1 полугодие" 2026 "Дополнительная" $env:KNP_OKED --submit

# 6. Отзыв поданного документа
node scripts/recall.js <регистрационный-номер> --submit
```

Скрипты подачи **по умолчанию останавливаются перед отправкой**. Реальное
юридически значимое действие происходит только с явным флагом `--submit`.

NCALayer должен быть запущен (слушает `127.0.0.1:13579`), браузер — headed:
нативный диалог требует настоящего экрана и фокуса.

## Скрипты

**Инфраструктура**
- `start-browser.js` — Chromium с профилем на диске и CDP-портом; перехватывает трафик к NCALayer
- `lib/browser.js` — подключение к браузеру по CDP
- `lib/form.js` — работа с ant-select по подписи поля

**ЭЦП**
- `nca-sign.ps1` — проход диалога NCALayer (пароль, выбор сертификата, подпись)
- `nca-cancel.ps1` — сброс зависшего диалога
- `uia-dump.ps1`, `coords.ps1` — диагностика дерева UI Automation и координат

**Кабинет**
- `login.js` — вход по ЭЦП
- `find-form.js` — поиск формы в каталоге
- `declare-910.js` — полный цикл 910.00
- `recall.js` — отзыв отчётности (007.00)
- `goto.js`, `inspect.js`, `dom.js`, `form-map.js`, `options.js`, `press.js` — разведка страниц

## Известные ограничения

- **Форма — SPA без сохранения состояния.** Любая навигация (`page.goto`)
  сбрасывает заполненные поля. Поэтому весь проход декларации идёт одним
  непрерывным сценарием.
- **Запрос в NCALayer живёт недолго.** Драйвер диалога надо запускать сразу
  после клика по кнопке подписи, иначе сайт перестаёт ждать ответ.
- **Отзыв не работает для «Дополнительной» декларации.** Форма 007.00 подтягивает
  данные отзываемого документа через
  `report-dictionary?requestCode=NZ_007_FNO_REG_NUMBER`. Проверено на шести
  реальных номерах одного налогоплательщика (номера здесь не приводятся —
  это персональные данные):

  | Вид декларации | Формат номера | Подана | Ответ справочника |
  |---|---|---|---|
  | Очередная | старый | 2025 | 200 ✅ |
  | Очередная | старый | 2026 | 200 ✅ |
  | Ликвидационная | новый (`…REP…TXF…`) | 2026 | 200 ✅ |
  | Дополнительная | старый | 2025 | 500 ❌ |
  | Дополнительная | старый | 2025 | 500 ❌ |
  | Дополнительная | новый (`…REP…TXF…`) | 2026 | 500 ❌ |

  Дело не в свежести документа и не в формате номера: 500 приходит для
  «Дополнительной» и годичной давности, 200 — для «Очередной» нового формата.
  Разделяющий признак ровно один — вид декларации.
  Без ответа справочника поля «Код/Вид налоговой отчётности» остаются
  заблокированными и пустыми, форму не отправить. Это ограничение КНП,
  а не автоматизации.
